# AppLockFP

تطبيق أندرويد أصلي (Kotlin + Android SDK + Gradle Kotlin DSL) يقفل
التطبيقات المختارة ويطلب **البصمة فقط** لفتحها — بدون أي خيار رمز
PIN أو كلمة سر بديلة.

## آلية العمل

1. **MainActivity** — تعرض كل التطبيقات المثبتة على الجهاز مع مفتاح
   (Switch) لكل تطبيق، تختار منها أي تطبيق تريد قفله.
2. **AppLockAccessibilityService** — خدمة إتاحة (Accessibility) تراقب
   أي تطبيق يُفتح في المقدمة. إذا كان من ضمن التطبيقات المقفلة، تفتح
   شاشة القفل فوراً قبل ما يقدر المستخدم يتفاعل مع التطبيق.
3. **LockActivity** — شاشة سوداء كاملة تطلب البصمة مباشرة عبر
   `BiometricPrompt` مضبوطة على `BIOMETRIC_STRONG` فقط (بدون
   `DEVICE_CREDENTIAL`)، فما يظهر أي خيار لإدخال رمز أو كلمة سر —
   بصمة فقط أو إلغاء. زر الرجوع (Back) معطّل بحيث يرجع للشاشة
   الرئيسية بدل ما يكشف التطبيق المقفل.
4. **حماية شاشة الإعدادات نفسها (MainActivity)** — الشاشة اللي فيها
   قائمة التطبيقات ومفاتيح التفعيل محمية بنفس آلية البصمة. بدون هذا،
   أي شخص يفتح AppLockFP نفسه ويطفي القفل عن أي تطبيق مباشرة بدون
   بصمة، وهذا يفرّغ فكرة التطبيق كاملة. كل مرة تختفي فيها هذه الشاشة
   (المستخدم يطلع منها) تُقفل من جديد تلقائياً وتطلب البصمة عند أي
   محاولة رجوع إليها.

## الأذونات المطلوبة من المستخدم (تُفعّل يدوياً من الإعدادات)

- **Accessibility Service**: عبر زر "تفعيل خدمة المراقبة" داخل
  التطبيق، يوديك مباشرة لإعدادات الأندرويد لتفعيلها.
- **بصمة مسجّلة على الجهاز**: من إعدادات الجهاز نفسه (الأمان → بصمة).
  التطبيق يتحقق ويعرض حالة "جاهزة ✔" أو "غير معدّة" في الشاشة
  الرئيسية.

```bash
pkg install git -y
cd AppLockFP
git init
git add .

git branch -M main
git remote add origin https://github.com/USERNAME/REPO.git

```

بعدها من تبويب **Actions** بصفحة المستودع، انتظر workflow "Build APK"،
وحمّل APK من قسم **Artifacts** باسم `applockfp-apk`.

## ملاحظات تقنية مهمة

1. **بصمة فقط دون بدائل**: هذا مضمون عبر
   `setAllowedAuthenticators(BiometricManager.Authenticators.BIOMETRIC_STRONG)`
   بدون دمج `DEVICE_CREDENTIAL`. حتى لو ضغط المستخدم "إلغاء"، ما
   يظهر له أي خيار PIN — فقط يرجع للشاشة الرئيسية.
2. **إعادة القفل التلقائي**: أي مرة ينتقل المستخدم لتطبيق آخر أو
   للشاشة الرئيسية، تُمسح حالة "مفتوح" لكل التطبيقات المقفلة، فيُطلب
   منه البصمة من جديد عند الرجوع لأي تطبيق مقفل.
3. **الخصوصية**: خدمة الـ Accessibility هنا لا تقرأ محتوى الشاشة
   (`canRetrieveWindowContent = false`) وتستخدم فقط حدث تغيّر
   النافذة (`typeWindowStateChanged`) لمعرفة اسم حزمة التطبيق
   المفتوح — هذا ضروري تقنياً لأي تطبيق قفل تطبيقات على أندرويد.
4. إذا رفض جهاز المستخدم تفعيل صلاحية Accessibility من إعدادات
   Google Play Protect (بعض الأجهزة تمنعها لتطبيقات غير منشورة على
   المتجر)، هذا قيد من نظام أندرويد نفسه وليس خطأ بالكود.
